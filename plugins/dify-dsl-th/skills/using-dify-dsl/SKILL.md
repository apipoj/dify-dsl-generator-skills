# using-dify-dsl

จุดเริ่มต้นของชุดทักษะ Dify DSL ทำหน้าที่เลือกเส้นทางและจำกัดบริบทที่ต้องอ่าน ส่วนรายละเอียดเฉพาะงานให้ใช้ skill ที่เกี่ยวข้อง

## เริ่มต้น

1. ตรวจว่างานเกี่ยวกับ Dify DSL หรือการเลือกเทมเพลต ตรวจสอบ แก้ไข หรือส่งมอบ `workflow`, `advanced-chat`, `rag_pipeline` จริง
2. แยกประเภทงานเป็นความต้องการยังไม่ชัดเจน สร้างใหม่ ตรวจแบบอ่านอย่างเดียว แก้ไขหรือปรับโครงสร้าง เลือกเทมเพลต หรือประเมินการส่งมอบ หากผู้ใช้ขอผู้ตรวจอิสระหลายฝ่ายหรือรวมผลที่ขัดแย้ง ให้แยกเป็นงานจัดการการตรวจทาน
3. ระบุขอบเขตจากคำขอและการอนุญาตที่มีอยู่แล้วว่าให้อ่านอย่างเดียว แสดงร่าง หรือเขียนไฟล์ ไม่ต้องขออนุญาตซ้ำในสิ่งที่ผู้ใช้อนุญาตแล้ว
4. เลือก skill หลักเพียงหนึ่งตัว และระบุ skill พื้นฐานที่จะใช้ต่อเมื่อจำเป็น
5. ถ้าเป้าหมายหรือขอบเขตยังไม่ชัด หรือเจตนาขัดแย้งกัน ให้เริ่มจาก brainstorming
6. ถ้าไม่ใช่งาน Dify DSL ให้แจ้งว่าอยู่นอกขอบเขตชุดทักษะนี้และหยุดส่งต่อ

## เลือกเส้นทาง

- ความต้องการยังคลุมเครือหรือขัดแย้งกัน → [dify-dsl-brainstorming](../dify-dsl-brainstorming/SKILL.md)
- เป้าหมายชัดและต้องการสร้าง DSL หรือร่างจากเทมเพลต → [dify-dsl-authoring](../dify-dsl-authoring/SKILL.md)
- ตรวจ DSL เดิมแบบอ่านอย่างเดียว ประเมินความเสี่ยง การนำเข้า หรือการเผยแพร่ → [dify-dsl-review](../dify-dsl-review/SKILL.md)
- แก้ไข ปรับประสิทธิภาพ หรือจัดโครงสร้าง DSL เดิม → [dify-dsl-refactor](../dify-dsl-refactor/SKILL.md)
- เลือกเฉพาะเทมเพลตหรือโครงร่าง ยังไม่สร้าง DSL → [dify-dsl-templates](../dify-dsl-templates/SKILL.md)
- ประเมินเฉพาะความพร้อมส่งมอบ โดยผ่านการตรวจโครงสร้างและฟิลด์แล้ว → [dify-dsl-governance](../dify-dsl-governance/SKILL.md)
- ขอการตรวจอิสระหลายฝ่าย จัดการ subagent หรือรวมความเห็นที่ขัดแย้ง → [dify-dsl-subagent-review](../dify-dsl-subagent-review/SKILL.md)

## หลักตัดสินใจ

- การขอข้อเสนอหรือถามว่าผิดตรงไหน ไม่ได้อนุญาตให้แก้ไฟล์โดยอัตโนมัติ
- การถามว่านำเข้า staging ได้หรือไม่ ไม่ใช่การอนุญาตให้ซ่อม
- ถ้าขอวิเคราะห์แล้วแก้ด้วยและอนุญาตชัด ให้ใช้ refactor หากยังไม่ชัด ให้ใช้ review หรือ brainstorming
- ถ้าผู้ใช้ระบุ skill โดยตรง ให้ใช้ตามนั้น ไม่ต้องเลือกเส้นทางใหม่
- กลับมาที่ตัวเลือกเส้นทางนี้เมื่อเป้าหมายเปลี่ยนหรือเลือกเส้นทางผิดเท่านั้น
- เคารพขอบเขตอ่านอย่างเดียว แม้จะพบปัญหาที่แก้ได้ทันที

## ผลลัพธ์ขั้นต่ำ

ระบุประเภทงาน ขอบเขตที่อนุญาต skill หลัก เหตุผลที่ไม่เลือกตัวใกล้เคียง 1–2 ตัว และ skill พื้นฐานที่คาดว่าจะต้องใช้ หากอยู่นอกขอบเขต ให้ระบุเหตุผลและไม่ส่งต่อ

## ข้อกำหนด

อ่านเฉพาะสิ่งที่จำเป็น อย่าโหลดทุก skill พร้อมกัน อย่าเขียน DSL ยาวก่อนเลือกเส้นทาง และอย่าดึงงานเขียนโปรแกรมทั่วไปหรือจัดเอกสารเข้ามาในชุดทักษะนี้

## ภาษาและแพลตฟอร์ม

อธิบายและถามเป็นภาษาไทย เว้นแต่ผู้ใช้ขอภาษาอื่น คงชื่อ skill, YAML keys, enum, node ID, selector, ชื่อ provider และ model ID ตามข้อกำหนดทางเทคนิค ห้ามแปลจนไฟล์ใช้งานไม่ได้ ข้อความที่ผู้ใช้เห็นและ prompt ภายใน workflow ใช้ภาษาไทยได้ตามโจทย์

เอกสารอ้างอิงเชิงเทคนิคและ fixtures ยังเป็นต้นฉบับ ให้อ่านแล้วอธิบายเป็นไทยโดยรักษาความหมาย แยกผลตรวจสคริปต์ออกจากการนำเข้าและรันบน Dify จริง ถ้าไม่มีเครื่องมือรันสคริปต์หรือ subagent ให้ระบุข้อจำกัด ห้ามอ้างว่าทดสอบหรือมีผู้ตรวจอิสระแล้ว
