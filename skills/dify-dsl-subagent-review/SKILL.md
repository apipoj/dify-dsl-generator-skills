# dify-dsl-subagent-review

จัดวิธีตรวจอิสระ เลือกเมื่อใดควรลดจำนวนผู้ตรวจ และรวมความเห็นที่ขัดแย้ง ไม่แทนตัวเลือกเส้นทางหรือหน้าที่หลักของ authoring, review, refactor และ governance

## เงื่อนไขเริ่มงาน

ประเภทงานหลักต้องชัดว่าเป็นการตรวจหลังสร้าง ตรวจอ่านอย่างเดียว ตรวจหลังแก้ หรือประเมินการส่งมอบ และผู้ใช้ขอการตรวจหลายฝ่ายหรือความซับซ้อนทำให้จำเป็นต้องตรวจอิสระเพื่อเพิ่มความน่าเชื่อถือ ทั้งนี้ต้องอยู่ภายใต้สิทธิ์และเครื่องมือของแพลตฟอร์ม

หากยังไม่ตรงเงื่อนไข ให้กลับไป [brainstorming](../dify-dsl-brainstorming/SKILL.md), [authoring](../dify-dsl-authoring/SKILL.md), [review](../dify-dsl-review/SKILL.md), [refactor](../dify-dsl-refactor/SKILL.md) หรือ [governance](../dify-dsl-governance/SKILL.md) ตามเป้าหมาย

## ลำดับการทำงาน

1. อ่าน [ดัชนีอ้างอิง](references/index.md)
2. เลือกรูปแบบจาก [ตารางเลือกรูปแบบการตรวจ](references/mode-selection-matrix.md)
3. เมื่อต้องกำหนดบทบาท อ่าน [บทบาทผู้ตรวจ](../dify-dsl-quality/agents/index.md)
4. แบบขนาน ใช้ผู้ตรวจอ่านอย่างเดียว 3 บทบาท ได้แก่ ข้อกำหนดฟิลด์ ความครบถ้วนของเส้นทางกราฟ และ prompt กับข้อตกลงข้อมูลเข้าออก
5. แบบตามลำดับ ตรวจโครงสร้างและฟิลด์ก่อน แล้วตรวจ prompt และข้อมูลเข้าออก สุดท้ายจึงรวมเกณฑ์ส่งมอบเมื่อจำเป็น
6. เพิ่มผู้ตรวจความพร้อมเผยแพร่เมื่อผลสามฝ่ายขัดกัน หรือโจทย์กำหนดให้รวมเกณฑ์เผยแพร่ ความครอบคลุม หรือการติดตามระบบ
7. ถ้าแพลตฟอร์ม เซสชัน หรือสิทธิ์ไม่อนุญาตผู้ตรวจ 3 ตัว ให้ลดตามลำดับ `3 -> 1 -> 0`

## รูปแบบการตรวจ

- **ขนาน** ใช้เป็นค่าเริ่มต้นเมื่อฟิลด์ กราฟ prompt และความเสี่ยงตรวจแยกได้
- **ตามลำดับ** ใช้เมื่อข้อสรุปรอบถัดไปขึ้นกับรอบก่อน เช่น ต้องยืนยันโครงสร้างก่อนประเมิน prompt
- **subagent เดียว** ใช้เมื่อความเสี่ยงแคบ ตัวอย่างเล็ก หรือสภาพแวดล้อมไม่เหมาะกับหลายตัว
- **ไม่มี subagent** ใช้เมื่อไม่มีเครื่องมือหรือไม่มีสิทธิ์ ต้องระบุว่า “ยังไม่ได้ตรวจโดยผู้ตรวจอิสระ” และเพิ่มระดับความเสี่ยงตามข้อจำกัดนั้น การตรวจหลายรอบด้วยผู้ช่วยตัวเดียวไม่ใช่การตรวจอิสระ

## ผลลัพธ์ขั้นต่ำ

ระบุงานหลัก รูปแบบที่ใช้ เหตุผลและรูปแบบใกล้เคียงที่ไม่ได้เลือก จำนวนและชื่อบทบาทที่ใช้งานจริง ปัญหาของแต่ละบทบาท จุดขัดแย้งและผลตัดสินถ้ามี ข้อสรุปรวม และความเสี่ยงคงเหลือพร้อมเหตุผลการลดรูปแบบ

## ข้อกำหนด

ห้ามให้ผู้ตรวจแก้ไฟล์ ห้ามให้ subagent เดียวรับทุกบทบาทแล้วอ้างว่าตรวจหลายฝ่าย ห้ามใช้ผู้ตรวจเผยแพร่แทนกระบวนการก่อนมีผลสามฝ่าย และห้ามอ้างว่าตรวจอิสระแล้วหากไม่มีเครื่องมือ สำหรับ authoring ให้ตรวจหลังมีร่าง ไม่เขียนร่างแทน authoring
